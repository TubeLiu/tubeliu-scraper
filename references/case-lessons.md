# 原始案例中可迁移的经验

经验来自经用户授权完成的 Switch 与多平台资料修复案例。使用本 skill 不需要读旧聊天或访问原设备。这里不保存私人聊天链接、真实账号、设备序列号、存储卡 ID、用户完整游戏资料和缓存。

- 原案例先修复小规模 Switch 游戏库，后修复涵盖多个平台的大规模游戏库。地区、版本、多碟、改版等分别算文件记录，不等于不同作品数；新任务重新盘点。
- 安卓 ES-DE 可以读取到 gamelist 文件，但 SAF 下绝对 ROM 路径没有匹配实际游戏。文件 hash 正确也不能证明元数据显示正确；统一为精确相对路径并在设备上目视验收。
- GB 两个文件同时有“绝对路径的资料节点”和“相对路径的仅历史节点”。直接替换一方会丢记录。合并时保留游玩次数、游玩时间、最近游玩和私有字段，冲突按原始证据审查。
- 某街机顶层文件被错指向子目录中的同名文件。仅字符串集合或覆盖重复键的字典检查会误通过；验证每个实际文件到唯一 XML 节点的双向映射。
- 一批媒体源复用于同作多个文件，上传量明显小于最终安装量。有效复用要保留已确认身份、来源和每个实际目标 hash；不能用上传字节代替安装覆盖率。
- 大量部署目标通过 SHA 后，另做实际引用、历史保护和设备显示检查，才封存完成。六类媒体完成时仍有未核实发行商、日期、人数等；不为“全绿”猜填事实。
- 真正 gameplay、截图预览与标题图预览分开统计。正确包装正面但错误包装侧面的 3D 图、纯绿色背面被备份后移除，不编造不存在的正确素材。
- Windows ADB 经 shell stdin 传 tar 曾截断；`exec-in` 的原始二进制流才是正确通道。大规模数据要打包并批量校验，逐文件独立调用非常慢。
- 安卓应用所有的只读主题目录无法直接修改；在已验证可写的父目录克隆、保留原目录后切换才完成。不把 chmod 或 root 当作普通修复步骤。
- 目视检查时屏保跳回游戏列表，确认键误启动模拟器，产生新的游玩历史。检查界面状态后才输入；若本次测试误启动，恢复仅该测试造成的变化。按键映射随设备和控制器变化，不固定背诵旧设备 keycode。
- 清理只删除当前暂存清单里的文件，原备份与未列出的素材保留；设备 32 位 shell 字节累计可能溢出，使用本地 64 位统计。

这些是工作判断依据，不是每个任务都需要执行的强制额外步骤。按当前用户范围、系统配置、授权和遇到的问题应用。
